# Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship light/dark/system theming for the XUNTAS+XUNTOS registration app, with a signed-in person's choice remembered on their account and followed across devices.

**Architecture:** Tailwind v4's `@theme` emits real CSS custom properties, and every utility compiles to `var(--color-…)`. Dark mode is therefore one override block on `:root[data-theme="dark"]`, not a component sweep. An inline script in `<head>` resolves the preference before first paint so there is no flash. A React context owns the preference; a separate zero-render component reconciles it with Convex once a session exists.

**Tech Stack:** TanStack Start + TanStack Router, React 19, Tailwind CSS v4, Convex, Clerk, Paraglide (i18n), Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-08-31-dark-mode-design.md` — read it before Task 1. Sections referenced below by number are that document's.

## Global Constraints

- **All user-facing copy lives in `messages/es.json` AND `messages/en.json`.** Never inline a string in a component. The two files must hold identical key sets; a key in one and not the other is what Paraglide reports as a missing message.
- **The brand yellow does not move.** `--color-yel: #ebf437` is identical in both themes, as are `--color-yel-line` and `--color-yel-d`.
- **The header band does not move.** Solid `#161615`, white text, yellow mark, in both themes.
- **Never use shadows.** Separation is done with a half tone or a translucent line (`docs/BRAND.md`).
- **Do not round the specific numbers.** 13.5px, 11.5px, 10.5px, 19px, 22px, 30px come from the approved prototype.
- **Yellow always carries an ink border.** Enforced by `--color-on-yel`.
- **Colour is never the only signal.** Any state carries a word as well.
- **Focus rings stay 3px with 2px offset.** Do not thin or remove.
- Run `npm run check` (typecheck + tests) before every commit step.

Create `src/lib/theme.ts`:

```ts
/**
 * Theme resolution, with no DOM and no React.
 *
 * The rules are here on their own so they can be tested as arithmetic — the
 * same reason `registrationRules.ts` and `cycle.ts` exist. Everything that
 * touches `localStorage`, `matchMedia` or the document lives in
 * `src/hooks/useTheme.ts` and imports from here.
 */

/** What the person chose. `system` means "follow the OS", and is the default. */
export type ThemePreference = 'system' | 'light' | 'dark'

/** What actually gets painted. `system` has already been resolved away. */
export type ResolvedTheme = 'light' | 'dark'

/**
 * Namespaced: on localhost this origin is shared with whatever else the
 * developer is running, and a bare `theme` key collides.
 */
export const THEME_STORAGE_KEY = 'xx-theme'

const PREFERENCES: ReadonlyArray<ThemePreference> = ['system', 'light', 'dark']

function isPreference(value: unknown): value is ThemePreference {
  return PREFERENCES.includes(value as ThemePreference)
}

/**
 * Parses whatever `localStorage` handed back.
 *
 * Anything unrecognised becomes `system` rather than throwing. The key is
 * writable from any browser console, and this value is stamped onto
 * `data-theme`; the only safe posture is to distrust it.
 */
export function readStoredPreference(raw: string | null): ThemePreference {
  return isPreference(raw) ? raw : 'system'
}

/** Collapses the three-state preference down to the two states CSS knows. */
export function resolveTheme(
  pref: ThemePreference,
  systemPrefersDark: boolean,
): ResolvedTheme {
  if (pref === 'system') return systemPrefersDark ? 'dark' : 'light'
  return pref
}

/**
 * The cycle the one button walks: system, then light, then dark, then back.
 *
 * Total by construction — an unrecognised input has an index of -1 and lands
 * on `system`, which is the right place for a value we do not understand.
 */
export function nextPreference(pref: ThemePreference): ThemePreference {
  return PREFERENCES[(PREFERENCES.indexOf(pref) + 1) % PREFERENCES.length]
}
```

- [ ] **Step 2: Add the pre-paint script to `RootDocument`**

Above the `RootDocument` function in `src/routes/__root.tsx`, add:

```tsx
/**
 * Resolves the theme before the browser paints anything.
 *
 * It is inlined into <head> as a string rather than routed through
 * `head().scripts` for two reasons: `headScripts` is typed `unknown` in
 * @tanstack/router-core, and running before first paint is the entire point —
 * a themed page that paints bone first and corrects on hydration is worse
 * than no dark mode at all.
 *
 * The key and the three valid values are duplicated from `src/lib/theme.ts`
 * because a string cannot import. `tests/theme.test.ts` pins the constant, so
 * changing it there fails the suite — which is the tripwire that sends whoever
 * changed it back to this string. Nothing checks this copy automatically.
 *
 * Wrapped in try/catch: Safari throws on `localStorage` under some privacy
 * settings, and a theme is not worth a blank page.
 */
const THEME_SCRIPT = `(function(){try{
var p=localStorage.getItem('xx-theme');
if(p!=='light'&&p!=='dark'&&p!=='system')p='system';
var d=p==='dark'||(p==='system'&&window.matchMedia('(prefers-color-scheme: dark)').matches);
document.documentElement.dataset.theme=d?'dark':'light';
}catch(e){document.documentElement.dataset.theme='light'}})()`
```

Then, inside `RootDocument`'s `<head>`, immediately after `<HeadContent />`:

```tsx
      <head>
        <HeadContent />
        <script dangerouslySetInnerHTML={{ __html: THEME_SCRIPT }} />
      </head>
```

```tsx
import {
  createContext,
  useCallback,
  useContext,
  useEffect,
  useMemo,
  useState,
} from 'react'
import {
  THEME_STORAGE_KEY,
  readStoredPreference,
  resolveTheme,
  type ResolvedTheme,
  type ThemePreference,
} from '../lib/theme'

type ThemeContextValue = {
  preference: ThemePreference
  resolved: ResolvedTheme
  /**
   * False during SSR and on the very first client render. The theme is not
   * knowable on the server, so anything that would render differently per
   * theme waits for this rather than causing a hydration mismatch.
   */
  mounted: boolean
  setPreference: (next: ThemePreference) => void
}

const ThemeContext = createContext<ThemeContextValue | null>(null)

export function useThemeContext(): ThemeContextValue {
  const ctx = useContext(ThemeContext)
  if (!ctx) throw new Error('useThemeContext must be used inside <ThemeProvider>')
  return ctx
}

const DARK_QUERY = '(prefers-color-scheme: dark)'

/**
 * Owns the theme preference.
 *
 * It sits ABOVE ClerkProvider, because Clerk has to be handed the resolved
 * theme for its own components. That is also why it knows nothing about
 * Convex: there is no session this high up. `ThemeSync`, further down the
 * tree, is the half that talks to the account.
 */
export default function ThemeProvider({ children }: { children: React.ReactNode }) {
  /*
   * Lazily initialised from what the pre-paint script already decided, so the
   * first client render agrees with the DOM instead of rendering `system` and
   * correcting in an effect.
   */
  const [preference, setPreferenceState] = useState<ThemePreference>(() => {
    if (typeof window === 'undefined') return 'system'
    try {
      return readStoredPreference(window.localStorage.getItem(THEME_STORAGE_KEY))
    } catch {
      return 'system'
    }
  })

  const [systemPrefersDark, setSystemPrefersDark] = useState(() => {
    if (typeof window === 'undefined' || !window.matchMedia) return false
    return window.matchMedia(DARK_QUERY).matches
  })

  const [mounted, setMounted] = useState(false)
  useEffect(() => {
    setMounted(true)
  }, [])

  /*
   * Subscribed only while the preference actually depends on the OS. Someone
   * who has pinned light does not need their machine's night schedule
   * re-rendering this tree at sunset.
   */
  useEffect(() => {
    if (preference !== 'system') return
    // jsdom has no `matchMedia` at all; `tests/setup.ts` stubs it, and this
    // guard means a harness that forgets to is a no-op rather than a crash.
    if (!window.matchMedia) return
    const mq = window.matchMedia(DARK_QUERY)
    setSystemPrefersDark(mq.matches)
    const onChange = (event: MediaQueryListEvent) => setSystemPrefersDark(event.matches)
    mq.addEventListener('change', onChange)
    return () => mq.removeEventListener('change', onChange)
  }, [preference])

  const resolved = resolveTheme(preference, systemPrefersDark)

  useEffect(() => {
    document.documentElement.dataset.theme = resolved
  }, [resolved])

  const setPreference = useCallback((next: ThemePreference) => {
    setPreferenceState(next)
    try {
      window.localStorage.setItem(THEME_STORAGE_KEY, next)
    } catch {
      /* Private mode. The choice still applies for this page's lifetime. */
    }
  }, [])

  const value = useMemo(
    () => ({ preference, resolved, mounted, setPreference }),
    [preference, resolved, mounted, setPreference],
  )

  return <ThemeContext.Provider value={value}>{children}</ThemeContext.Provider>
}
```

```tsx
import { useThemeContext } from '../ThemeProvider'
import { nextPreference, type ThemePreference } from '../../lib/theme'
import Icons from '../Icons'
import * as m from '../../paraglide/messages.js'

const ICON = {
  system: Icons.ThemeSystem,
  light: Icons.ThemeLight,
  dark: Icons.ThemeDark,
} as const

const NAME: Record<ThemePreference, () => string> = {
  system: m.theme_system,
  light: m.theme_light,
  dark: m.theme_dark,
}

/**
 * One button, three states.
 *
 * A cycling control is smaller than a segmented one and harder to read — the
 * state is only legible from the icon, and pressing it is the only way to
 * find out where it goes. That cost is paid down here and not elsewhere:
 * three distinct shapes, a label naming both the current state and the next
 * action, and a live region, because a button whose own label changes under
 * the cursor is not otherwise announced.
 */
export default function ThemeToggle() {
  const { preference, mounted, setPreference } = useThemeContext()
  const upcoming = nextPreference(preference)

  /*
   * The theme is not knowable on the server. Rendering the real icon before
   * mount would be a hydration mismatch; rendering nothing would collapse the
   * header's layout and shift the nav. The system icon at full size is
   * neither.
   */
  const Icon = mounted ? ICON[preference] : Icons.ThemeSystem
  const label = `${m.theme_label()}: ${NAME[preference]()}. ${m.theme_switch_to({ theme: NAME[upcoming]() })}`

  return (
    <>
      <button
        type="button"
        onClick={() => setPreference(upcoming)}
        aria-label={label}
        title={label}
        className="inline-flex size-[30px] flex-none items-center justify-center rounded-full text-white/72 transition-colors hover:bg-white/10 hover:text-white"
      >
        <Icon className="size-[15px]" />
      </button>
      <span aria-live="polite" className="sr-only">
        {mounted ? `${m.theme_label()}: ${NAME[preference]()}` : ''}
      </span>
    </>
  )
}
```

```ts
/**
 * Stores the reader's theme.
 *
 * Deliberately trivial: no rate limit, no audit trail, nothing derived. It is
 * a display preference, and treating it with the ceremony of the registration
 * data would be miscalibrated.
 */
export const setThemePreference = mutation({
  args: { preference: vThemePreference },
  handler: async (ctx, args) => {
    const user = await requireUser(ctx)
    await ctx.db.patch(user._id, {
      themePreference: args.preference,
      updatedAt: Date.now(),
    })
    return { ok: true as const }
  },
```

- [ ] **Step 1: Write the sync component**

Create `src/components/ThemeSync.tsx`:

```tsx
import { useEffect, useRef } from 'react'
import { useMutation, useQuery } from 'convex/react'
import { api } from '../../convex/_generated/api'
import { useThemeContext } from './ThemeProvider'
import type { ThemePreference } from '../lib/theme'

/**
 * Reconciles this browser's theme with the signed-in account. Renders nothing.
 *
 * It is a separate component from `ThemeProvider` because of where each has
 * to sit: the provider is above ClerkProvider, so Clerk can be handed the
 * resolved theme, and there is no session that high in the tree. This half
 * lives inside the Convex provider, where there is one.
 *
 * The rule, from the spec: an explicit SAVED preference wins over this
 * browser's cache. That is what makes "remember my preference" true on a
 * borrowed laptop. An account with nothing saved instead adopts whatever this
 * browser had, and pushes it up.
 */
export default function ThemeSync() {
  const { preference, setPreference } = useThemeContext()
  const account = useQuery(api.users.myThemePreference)
  const save = useMutation(api.users.setThemePreference)

  /*
   * Without these two refs the effects feed each other: applying the server's
   * value changes `preference`, which the write-back effect would then push
   * straight back to the server.
   */
  const reconciled = useRef(false)
  const lastPushed = useRef<ThemePreference | null>(null)

  // `undefined` is still loading; `null` is signed out. Both mean "not yet".
  useEffect(() => {
    if (account === undefined || account === null) return
    if (reconciled.current) return
    reconciled.current = true

    if (account.preference !== null) {
      lastPushed.current = account.preference
      setPreference(account.preference)
    } else if (preference !== 'system') {
      // Nothing saved, and this browser has an opinion. Adopt it.
      lastPushed.current = preference
      void save({ preference })
    }
  }, [account, preference, setPreference, save])

  useEffect(() => {
    if (!reconciled.current) return
    if (account === undefined || account === null) return
    if (lastPushed.current === preference) return
    lastPushed.current = preference
    void save({ preference })
  }, [preference, account, save])

  /*
   * Signing out must reset the gate, or signing in as someone else in the
   * same tab would skip reconciliation and leave the previous person's theme.
   */
  useEffect(() => {
    if (account === null) {
      reconciled.current = false
      lastPushed.current = null
    }
  }, [account])

  return null
}
```

- [ ] **Step 2: Rewrite the appearance as a function of the theme**

Replace the body of `src/lib/clerkAppearance.ts`:

```ts
import type { Appearance } from '@clerk/types'
import type { ResolvedTheme } from './theme'

/**
 * Clerk in XUNTAS's skin.
 *
 * Clerk's components bring their own design and, without this, the sign-up
 * looks like any SaaS's: blue, rounded, foreign. The variables cover 90%; the
 * `elements` fix what the variables cannot reach.
 *
 * A function of the theme rather than a constant, and resolved hexes rather
 * than `var(--color-…)`: Clerk derives whole colour scales from `colorPrimary`,
 * and a `var()` reference defeats that arithmetic — it would get a string it
 * cannot lighten or darken.
 *
 * Prefer `elements` over `variables` wherever both could do the job. The
 * `elements` half is Tailwind classes over our own tokens, so it follows the
 * theme with no work and cannot drift; the `variables` half is duplicated
 * hexes that can.
 */
export function clerkAppearance(theme: ResolvedTheme): Appearance {
  const dark = theme === 'dark'
  return {
    variables: {
      colorPrimary: dark ? '#fafaf8' : '#161615',
```

```markdown
**There is a dark mode, and it is derived.** It was not in the 2025 guideline —

> A token naming a role relative to the **page** inverts, and everything using
```

```markdown
## Dark mode, and where its palette came from

Added 2026-08-31, reversing a decision this file and `BRAND.md` had both

The 2025 Brands&People guideline has no dark palette, so ours is derived: the
page inverts to the warm black, the bone becomes the text, and the brand yellow

Three things are worth knowing before touching it.

**The palette is one CSS block, not a component sweep.** Tailwind v4 emits

this app uses. An explicit saved preference beats the browser's cache on
sign-in, which is what makes it useful on a borrowed laptop. `users.update`,
the Clerk mirror, does not touch the field.
```
